# Progress — индикаторы загрузки

Два варианта одного компонента: **linear** — полоса, **circular** — кольцо. Каждый
работает в двух режимах: `determinate` (известна доля) и `indeterminate` (известен
только сам факт работы).

- [references/progress-linear.md](references/progress-linear.md) — полоса, разметка, поведение
- [references/progress-circular.md](references/progress-circular.md) — кольцо, `pathLength`
- [references/preview.html](references/preview.html) — storybook: обе оси, тёмный островок

Механика взята из [Material Web · progress](https://github.com/material-components/material-web/blob/main/docs/components/progress.md),
геометрия — из [макета](https://www.figma.com/design/UCYhMA1JeNUNuVGsxUEne7/%F0%9F%92%A0-Comp-%E2%86%AA-%C2%B9-Elemets?node-id=2093-3033).

## Главное про контракт

**Значение — число 0…100 в `--awds-progress-value`, а не процент.** Круговому варианту
это же число нужно для `stroke-dasharray` (при `pathLength="100"`), поэтому один формат
избавляет потребителя от двух.

```html
<div class="progress progress-linear" style="--awds-progress-value: 50"
     role="progressbar" aria-valuenow="50" aria-valuemin="0" aria-valuemax="100"
     aria-label="Загрузка файла">
  <span class="progress-linear__active"></span>
  <span class="progress-linear__track"><span class="progress-linear__stop"></span></span>
</div>
```

**`aria-valuenow` меняется вместе с переменной.** Скринридер не читает CSS, поэтому
обновление прогресса — это всегда две записи: переменная и атрибут.

**У indeterminate `aria-valuenow` нет.** Атрибут со значением обещал бы известную долю.
По той же причине скрывается точка-стоп: она обозначает финиш.

## Что решено в CSS, а не отдано потребителю

| Ситуация | Поведение |
| --- | --- |
| значение 100% | трек и точка исчезают сами: трек начинается после активной части плюс зазор и уезжает за край |
| значение 0% у кольца | обводка гасится `stroke-opacity: min(1, calc(value * 1000))` — иначе круглый linecap рисует точку «немного загрузилось» |
| значение меняется | `transition`, а не keyframes: значение приходит скачками, переход перехватывает движение с текущей точки |
| `prefers-reduced-motion` | полоса перестаёт бегать и пульсирует, кольцо перестаёт вращаться, но дуга продолжает дышать |

## Токены

Геометрия целиком легла на шкалу Space — ни одного собственного числа:
`space-3` область, `space-1` полоса и точка, `space-1-5` зазор, `space-0-5` толщина дуги,
`space-12` диаметр. Радиус — `--awds-rounded-border-radius-full`. Цвет — роль
`rgb(var(--surface-on))`, трек и точка под `--awds-opacity-opacity-20`.

Свои значения (в `own_values` меты): `1.4s` — длительность цикла indeterminate
(коллекции движения в студии нет; значение согласовано со спиннером кнопки) и `30%` —
доля ширины бегущей полосы, то есть форма анимации, а не размер интерфейса.

## Чего в компоненте нет и почему

- **Шкалы размеров.** В макете один размер, ступеней Size у прогресса в теме тоже нет.
  Толщину можно переопределить переменной, но `.progress--{N}` появится только после
  того, как дизайнер заведёт ступени в студии.
- **Трека у кольца.** В макете нарисована только активная дуга.
- **Буфера** (вторая полоса под активной) и **`four-color`** из Material — в макете их нет.
- **Трёх сегментов активной полосы.** В Figma она нарезана на `Segment-start / Segment /
  Segment-end` — заготовка M3 под волнистый индикатор (слои названы `wave-increment`).
  Волна выпрямлена: все три сегмента — прямая линия, поэтому в CSS одна полоса.

## Где применять

Ожидание с известной долей — загрузка файла, импорт, шаг мастера. Ожидание без доли —
запрос к серверу, пересчёт. **Внутри кнопки не нужен:** у кнопки свой спиннер
(`.btn__progress` при `.btn--loading`).
