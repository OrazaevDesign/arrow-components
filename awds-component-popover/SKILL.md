# Popover (панель-поповер) ArrowDS

Панель с тенью и хвостом-стрелкой, указывающим на «якорь», **со слотом под произвольное содержимое**. Своего контента у компонента нет: меню, календарь, фильтр или карточку-превью кладёт внутрь потребитель. Ничего не хардкодит: цвета — роли, скругление и тень — токены DS. См. скилл `arrow-design-system`.

Компонент **статичный** — это только внешний вид панели. Показ, скрытие и позиционирование рядом с якорем реализует потребитель.

## Когда использовать

| Нужно | Компонент |
|---|---|
| Панель с хвостом под произвольное содержимое: меню, календарь, фильтр | **`awds-component-popover`** (этот) |
| Короткий поясняющий текст в пузыре | `awds-component-tooltip` — внутри только текст, со своим кеглем и паддингами |
| Раскрытый список нативного `<select>` | `awds-component-select` — панель рисуется псевдоэлементом `::picker(select)`, хвоста у неё нет |
| Модальное окно поверх затемнения | секция `↪ modal` макета; компонента пока нет |

Три вещи в библиотеке легко спутать, потому что все три — «выпадашка»:

- **popover** (этот) — оболочка с **хвостом**, содержимое слотом, одна ступень;
- **`/ dropdown`** — панель раскрытого списка `select` на **семи ступенях**, без хвоста, своего кода не имеет (это `::picker(select)` у `select` и `select-combi`);
- **панель `datepicker`** — своя рамка календаря, читает ячейки `size/dropdown/400/*`.

## Ось

Ось одна — сторона. Тонов и ступеней размера нет: панель одна, различается только тем, с какой стороны якоря висит.

| Ось | Класс | Значения |
|---|---|---|
| **side** | `.pop--side-{side}` | `top` (по умолчанию) · `bottom` · `left` · `right` |
| **show-tail** (булево в макете) | элемент `.pop__tail` в разметке | есть элемент — хвост есть; нет элемента — панель без хвоста |

**Side = с какой стороны якоря висит панель, хвост смотрит НА якорь:** `top` → панель сверху, хвост снизу; `bottom` → снизу, хвост сверху; `left` → слева, хвост справа; `right` → справа, хвост слева. То же правило, что у `tooltip`.

## Содержимое — слот

С 29.09.2026 содержимое в макете — **нативный слот Figma `content`** внутри панели, пустой по умолчанию: вставляется что угодно, не только компонент. До этого была заглушка `. / swap` под свойством замены, и ради каждого содержимого приходилось заводить компонент-обёртку. В коде ничего не меняется: `.pop__panel` и раньше принимал любую разметку.

## Паддинга у панели нет

В макете у панели нет внутренних отступов — их приносит содержимое: у списка свои, у календаря свои. Ставить паддинг в компоненте значило бы складывать два у каждого потребителя. Это отличие от `tooltip`, где текст лежит прямо в пузыре и паддинг принадлежит подсказке.

## Откуда берутся значения

| Что | Источник |
|---|---|
| Фон панели и хвоста | `rgb(var(--surface-bright))` — ячейка `popover/bg` |
| Хайрлайн-обводка хвоста | `rgb(var(--extended-shadow-3))` — ячейка `popover/hairline`, это кольцевой слой тени панели (чёрный 3%) |
| Тень | `var(--awds-shadow-elevation-3)` |
| Скругление | `var(--awds-rounded-border-radius-600)` (10px) — на ступень выше тултипа (8px): панель крупнее пузыря, и в макете это разные токены |
| Хвост | треугольник 16×6 (`--awds-pop-tail-base` = space-4, `--awds-pop-tail-depth` = space-1-5) снаружи ребра панели, по центру стороны, без drop-тени; хайрлайн 1px — тот же треугольник со сдвигом наружу |

Состояний нет. Маппинг зафиксирован в `component.meta.json` + `snapshot/figma.json`. Обновление — через `arrow-components-builder` («обнови awds-component-popover»).

## CSS

Один файл — `references/popover.css` (база `.pop` + `.pop__panel` + `.pop__tail` + стороны `.pop--side-{top,bottom,left,right}`). Подключается один раз глобально.

Базовый класс **`.pop`, а не `.popover`**: `.popover` почти наверняка занято на стороне потребителя (так зовётся компонент в Bootstrap), а приватные аккумуляторы по контракту зовутся `--awds-{base_class}-*`. Тот же приём, что у `label` → `.lbl`, `datepicker` → `.dpick`.

Хвост — треугольник 16×6, как вектор `shape` в макете: `.pop__tail` прозрачен и задаёт бокс снаружи ребра панели, `::after` рисует треугольник цветом панели, `::before` — хайрлайн со сдвигом 1px наружу (вектор `hairline` в макете). Без drop-тени — лежит на тени бокса. Узлы хвоста в макете совпадают с тултипом один в один, приём тот же. **До 27.09.2026** здесь был повёрнутый на 45° квадрат 8px (основание 11.3 вместо 16) — сверка с макетом числом (`component-figma-check`) вернула макетную геометрию.

У панели стоит `overflow: hidden` — содержимое приходит слотом, и без клипа его углы торчали бы за скругление (в макете у узла `content` стоит clip).

Визуальный QA — `references/preview.html` (storybook): четыре стороны × два вида содержимого на светлой и тёмной теме.

## Алгоритм использования

1. Выбери сторону (`top`/`bottom`/`left`/`right`) — ту, с которой панель висит относительно якоря.
2. Разметка — обёртка `.pop` + хвост `.pop__tail` + панель `.pop__panel`:
   ```html
   <span class="pop pop--side-top">
     <span class="pop__tail"></span>
     <span class="pop__panel">…содержимое…</span>
   </span>
   ```
   Tail должен идти ПЕРЕД панелью (панель рисуется поверх и перекрывает внутреннюю половину хвоста). Хвост не нужен — не клади `.pop__tail` вовсе (в макете `show-tail=off`), сторона `.pop--side-*` тогда ни на что не влияет.
3. Отступы внутри — на содержимом, не на панели.
4. Показ и скрытие: нативный `popover` (Baseline 2024) — атрибут `popover` на `.pop` и `popovertarget` на кнопке; UA-стили компонент снимает сам. Позиционирование рядом с якорем — своё: anchor positioning вне планки Baseline 2024.
5. Доступность: кнопке-триггеру `aria-expanded`, панели с меню — `role="menu"` у списка внутри; сама панель семантики не несёт, она оболочка.
6. Подключи `references/popover.css`. Нужны `css-variables.css` сайта (роли `--surface-*`, `--extended-*`) и базовые токены DS (`--awds-space-*`, `--awds-rounded-*`, `--awds-shadow-elevation-3`).
