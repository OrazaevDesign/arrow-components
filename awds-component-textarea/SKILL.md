# Textarea ArrowDS

Многострочное поле ввода: тот же контрол-прямоугольник, что и [`awds-component-input`](../awds-component-input/SKILL.md), но на три строки и с ручкой ресайза в правом нижнем углу. Палитра `form-control` общая со всем семейством форм — рядом в одной форме поля выглядят одинаково. Размеры, цвета и типографика — из токенов DS, ничего не хардкодится.

## Разметка

```html
<label for="comment">Комментарий к заказу</label>
<span class="txa txa-default txa--400">
  <textarea class="txa__field" id="comment" placeholder="Например: позвонить за час"></textarea>
</span>
```

- **Подпись — снаружи.** Combi-версии (метка внутри рамки) у этого компонента в скилле нет; в макете она существует отдельным семейством `Textarea Combi`, это другой компонент.
- **Слотов нет.** У `input` и `select` в обёртку кладут иконки; здесь их не бывает — и поэтому горизонтальный отступ текста всегда `text-gap`, без развилки.
- **`rows` не обязателен.** Три строки уже заданы через `min-block-size`. `rows="5"` сделает поле выше, `rows="2"` — не сделает ниже.

## Размерные модификаторы

| Класс | Высота | Типографика | Когда |
|---|---|---|---|
| `txa--50` | 52px | 12/16 | Технические поля, плотные таблицы |
| `txa--100` | 56px | 13/16 | Плотные формы |
| `txa--200` | 64px | 13/16 | Компактные формы |
| `txa--300` | 76px | 14/20 | Плотные формы обычной типографики |
| `txa--400` | 80px | 14/20 | **По умолчанию** — обычные формы |
| `txa--500` | 88px | 16/20 | Ключевые поля: отзыв, обращение |
| `txa--600` | 92px | 16/20 | Тач-интерфейсы, крупные формы |

Высота не задаётся явно: **`2 × padding + 3 × line-height`** — три строки. Это `min-block-size`, то есть **минимум**, а не фиксированная высота: `rows` и ресайз пользователем могут её увеличить. Ширина — `100%`; 320px в макете это ширина демо-фрейма.

## Ручка ресайза

Самое интересное место компонента.

- **Иконка — псевдоэлемент обёртки** (диагональ из макета, `ic20-textareaControl-outline`), цвет — роль текста при `opacity: 30%`. Она красится вместе с текстом: при фокусе уходит в брендовую роль.
- **Системный уголок Chromium выключен** (`::-webkit-resizer { display: none }`) — его полосок в макете нет. Выключен только **вид**: тяга остаётся нативной, псевдоэлемент её не перехватывает (`pointer-events: none`).
- **`resize: vertical`, а не `both`** — осознанное отклонение: контрол тянется на всю ширину контейнера, и горизонтальная тяга позволила бы вытащить поле за пределы формы. В макете нарисована статичная иконка, ось не задана.
- **`.txa--fixed`** снимает ресайз **вместе с ручкой**: показывать хват, которого нет, — обман.
- **В `disabled` ручка остаётся видимой** и гаснет вместе со всем контролом — так в макете. Сам ресайз при этом снят.
- **Firefox** не поддерживает `::-webkit-resizer`, там останется системная ручка поверх нашей. Единственное известное расхождение; работу не ломает.

## Откуда берутся значения

| Что | Источник | Где живёт |
|---|---|---|
| Цвета состояний (bg/chroma/border/текст/плейсхолдер) | `rgb(var(--secondary-container-*))`, `rgb(var(--primary-container-*))`, `rgb(var(--surface-bright))` inline | `references/textarea-default.css` |
| Фокус-кольцо | `rgb(var(--primary-core) / var(--awds-opacity-50))`, offset 1 | Figma `focus-selection/outlineVariant` + `opacity/50` |
| Геометрия (padding/rounded) | `var(--awds-rectangle-{N}-*)` | `component-token-map.json` → `map.size.rectangle` |
| Горизонтальный отступ текста | `var(--awds-rectangle-{N}-text-gap)` — всегда, слотов нет | Figma: auto-layout ячейки |
| Типографика | `var(--awds-rectangle-{N}-typography-*)` → `control-{M}` | там же |
| Приглушение ручки | `var(--awds-opacity-30)` | `map.state.rest.content.textarea-handle` |
| Бокс ручки | `var(--awds-space-5)` — 20px фикс на всех размерах | базовая шкала, не `rectangle-{N}-icon` |
| Opacity для disabled | `var(--awds-opacity-40)` | css-global (базовая шкала) |
| Базовая палитра | RGB-триплеты ролей `--{role}` | `css-variables.css` сайта |

**Базовый класс — `.txa`, а не `.textarea`.** Приватные аккумуляторы зовутся `--awds-{base_class}-*`; при `base_class = textarea` они читались бы как чужой компонентный токен `--awds-textarea-*` (такого слоя в DS нет), а `.textarea` на элементе `<textarea>` — тавтология.

## Четыре вещи, которые легко сделать неправильно

1. **Поставить `height` вместо `rows`.** Высота компонента — `min-block-size` из трёх строк; жёсткий `height` сломает и `rows`, и ресайз, и поле перестанет расти под содержимое.
2. **Ждать развилки `padding` / `text-gap`.** У `input` и `select` горизонталь переключается по наличию иконки; здесь слотов нет, и `text-gap` действует всегда. Не копируй правило `:has(> .prefix)` из соседних компонентов.
3. **Оставить `resize: both`.** Поле шириной 100% пользователь вытащит за пределы формы. Если нужна фиксация — `.txa--fixed`, а не переопределение `resize` руками (иначе ручка останется врать).
4. **Фокус гасит hover через `:not(:focus-within)`, а не порядком правил.** `:has()` в hover-селекторе даёт (0,5,0) против (0,2,0) у `:focus-within` — без `:not()` наведение на сфокусированное поле подменяло бы брендовую рамку серой.

## Доступность

- Поле остаётся нативным: клавиатура, проверка орфографии, отправка формы, `maxlength` работают сами.
- **Подпись обязательна** — `<label for>` рядом. Плейсхолдер подписью не является: он исчезает при вводе.
- Фокус виден при любом способе входа в поле (`:focus-within`); кольцо стоит **в 1px от рамки**, не вплотную.
- Ресайз пользователем — это **функция доступности**: человеку с крупным шрифтом или длинным текстом нужна возможность увеличить поле. Не отключай `.txa--fixed` без причины.
- Если у поля есть лимит символов, счётчик ставится **снаружи** и связывается через `aria-describedby`; в этом компоненте его нет.
- Disabled гасится `opacity: var(--awds-opacity-40)` на всей обёртке — макетное поведение, контраст в этом состоянии заведомо ниже AA. Рядом нужен текст-причина, а не только серость.

## Варианты

Шесть — весь набор семейства. Палитра `form-control/*` общая с `input`, `select` и их combi-версиями: рядом в одной форме контролы совпадают по цвету. `secondary` тут нет, как и у `select`.

Выбор варианта — от **фона, на котором стоит поле**, а не от важности поля:

| Вариант | Класс | Фон в покое | Когда |
|---|---|---|---|
| **default** | `.txa-default` | `secondary-container-core` — серый | Поле на белой странице |
| **light** | `.txa-light` | `surface-bright` — белый | Поле на сером блоке: карточка, панель, модалка |
| **success** | `.txa-success` | `success-container-core` — зелёный | Текст прошёл проверку |
| **error** | `.txa-error` | `error-container-core` — красный | Текст не прошёл проверку или поле пустое |
| **autofill** | `.txa-autofill` | `tertiary-container-core` — синий | Текст подставило приложение, а не пользователь |
| **ghost** | `.txa-ghost` | прозрачный | Границу задаёт окружение: ячейка таблицы, инлайн-правка |

**success / error / autofill — это состояния значения**, а не виды контрола: класс вешается и снимается по ходу валидации. У `error` цвета мало — нужны `aria-invalid` и текст причины (см. [textarea-error.md](references/textarea-error.md)).

**Два варианта ведут себя не как все**, и это сверено по ячейкам макета:

- **ghost** — на hover и active **ничего не подсвечивается** (все три ячейки прозрачны), правил в CSS нет намеренно. У многострочного поля он рискованнее, чем у кнопки: в покое видны только текст и ручка в углу.
- **light** — фокус **не меняет фон**: он и в покое `surface-bright`. Меняются chroma, рамка и цвета текста.

Ручка ресайза во всех вариантах красится **цветом текста своего варианта** при `opacity: 30%` — отдельного правила у неё нет, она следует за `--awds-txa-color`.

Отдельно на той же странице макета лежит семейство **`Textarea Combi`** — многострочное поле с плавающей меткой. Это **другой компонент** (как `select` vs `select-combi`), в этот скилл он не входит.

| Вариант | Файл | Reference |
|---|---|---|
| default | `references/textarea-default.css` | [textarea-default.md](references/textarea-default.md) |
| light | `references/textarea-light.css` | [textarea-light.md](references/textarea-light.md) |
| success | `references/textarea-success.css` | [textarea-success.md](references/textarea-success.md) |
| error | `references/textarea-error.css` | [textarea-error.md](references/textarea-error.md) |
| ghost | `references/textarea-ghost.css` | [textarea-ghost.md](references/textarea-ghost.md) |
| autofill | `references/textarea-autofill.css` | [textarea-autofill.md](references/textarea-autofill.md) |

Каждый файл **самодостаточен**: содержит базу `.txa` (побайтово одинаковую), семь размеров, ручку, `--fixed`, свой блок варианта и reduced-motion. Подключается только нужный вариант.

## Алгоритм использования

1. Возьми разметку из [references/textarea-default.md](references/textarea-default.md) — обёртка, поле, `<label for>` снаружи.
2. Подключи CSS нужного варианта (`textarea-{вариант}.css`) — один раз глобально.
3. Убедись, что на странице есть DS-токены (`--awds-rectangle-*`, `--awds-control-*`, `--awds-opacity-*`, `--awds-space-*`, `--awds-font-*`) и сайтовый `css-variables.css` с цветовыми ролями под классом `.theme-default.theme-light` на `<html>`.
4. Поставь класс варианта (`txa-default`) — без него поле останется бесцветным — и размерный модификатор `.txa--{N}` (если не указан, действует 400).
5. Ширину задай контейнеру-родителю: поле тянется на 100%.
