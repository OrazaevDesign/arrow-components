## Три слоя звезды

Выбранная и пустая звезда в макете — **разные векторы**: `shape-star-filled` (сплошная) и
`shape-star-duotone` (контур плюс внутренняя заливка на 30%). Поэтому в разметке лежат
три контура сразу, а CSS показывает нужные:

| Слой | Класс | Когда виден | Цвет |
| --- | --- | --- | --- |
| внутренняя заливка | `.rating__ghost` | звезда пустая | `unselected-bg` при `fill-opacity: 30%` |
| контур | `.rating__outline` | звезда пустая | `unselected-bg` |
| сплошная | `.rating__solid` | звезда набрана | `selected-bg` |

Видимость ведёт одна переменная `--awds-rating-picked` (1 или 0), зарегистрированная через
`@property` как `<number>` — иначе слои переключались бы скачком, без перехода.

## Как красятся звёзды

CSS не умеет выбирать «предыдущих братьев», поэтому логика обратная: красим **все**
звёзды, а затем гасим те, что стоят **после** выбранной.

```css
.rating:has(.rating__input:checked) .rating__star         { --awds-rating-picked: 1; }
.rating__star:has(.rating__input:checked) ~ .rating__star { --awds-rating-picked: 0; }
```

То же с наведением, но у него две особенности, и обе куплены багом.

**Зазор живёт внутри звезды, а не между звёздами.** Через `gap` между соседями оставалась
полоса, не принадлежащая никому. Курсор над ней — это `:hover` на контейнере без `:hover`
на звезде: включающее правило срабатывало, гасить было нечего, и загорались все пять.
На глаз — мерцание при проводке курсора и «выбраны все». Теперь `gap: 0`, а половина
зазора лежит паддингом внутри каждой звезды (у крайних — только с внутренней стороны,
иначе компонент стал бы шире макета). Проверено: по всей ширине компонента нет ни одной
точки, не принадлежащей звезде, а ширина совпадает с макетом — 124 / 88 / 68 px.

**Оба hover-правила несут `:has` для выравнивания веса.** Селектор с `:has` весит столько
же, сколько самый тяжёлый аргумент внутри. Поэтому короткое гасящее правило
`.rating__star:hover ~ .rating__star` (0,3,0) проигрывало включающему
`.rating:has(.rating__star:hover) .rating__star` (0,4,0) — и звёзды снова загорались все.
Гасящее пришлось утяжелить тем же `:has` до (0,6,0):

```css
.rating:has(.rating__star:hover) .rating__star                        { --awds-rating-picked: 1; }
.rating:has(.rating__star:hover) .rating__star:hover ~ .rating__star  { --awds-rating-picked: 0; }
```

Наведение перебивает выбор: выбрано 5, курсор на второй — видно «будет 2», и цвет берётся
из `selected-bg-hover`. Оба правила под `@media (hover: hover)` — на тач-экране «наведение»
залипает после тапа.

Требование к порядку: звёзды идут 1→5. Обратный DOM с `row-reverse` дал бы ту же
картинку одним селектором, но стрелки клавиатуры поехали бы в обратную сторону.

## Выключено

```html
<input class="rating__input" type="radio" name="rate" value="3" disabled>
```

Атрибут обязателен: класс `.rating--disabled` только красит. `pointer-events: none`
гасит мышь, но не клавиатуру — на range это уже стоило версии 1.0.3.

## Размеры

| Класс | Звезда | Зазор |
| --- | --- | --- |
| `.rating--400` (по умолчанию) | 20px (`space-5`) | 6px (`space-1-5`) |
| `.rating--300` | 16px (`space-4`) | 2px (`space-0-5`) |
| `.rating--200` | 12px (`space-3`) | 2px (`space-0-5`) |

## Чего нет

- **Половин звезды** — в макете нет.
- **JS** — не нужен: выбор держит radio. Реакция на выбор — `change` на `.rating__input`.
- **Своих значений** — все размеры и цвета ссылками на тему.
