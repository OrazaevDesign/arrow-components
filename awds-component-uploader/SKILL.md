# Uploader ArrowDS

Загрузка файлов: сверху поле выбора, снизу список загруженного. Компонент композиционный — поле и кнопку удаления берёт готовыми, а сам рисует список и строку файла.

## Разметка

```html
<div class="upl upl--400">
  <label class="upl__label">
    <input class="upl__input" type="file" multiple>
    <span class="input input-default">
      <input class="input__field" type="text" placeholder="Выберите файл" readonly tabindex="-1">
      <span class="input__suffix" aria-hidden="true">
        <svg viewBox="0 0 20 20"><!-- ic20-upload --></svg>
      </span>
    </span>
  </label>

  <ul class="upl__list">
    <li class="upl__file">
      <span class="upl__preview"><img src="…" alt=""></span>
      <span class="upl__content">
        <span class="upl__name">wp.png изображение 1</span>
        <span class="upl__size">324 kb</span>
      </span>
      <span class="upl__progress"><!-- индикатор --></span>
      <button type="button" class="btn btn-ghost btn--300 btn--icon-only upl__remove" aria-label="Удалить wp.png">
        <svg viewBox="0 0 20 20"><!-- ic20-closeMini --></svg>
      </button>
    </li>
  </ul>
</div>
```

Строка файла с иконкой типа вместо превью — `.upl__icon` на месте `.upl__preview`; файл с ошибкой — модификатор `.upl__file--error` на `<li>`.

## Почему поле устроено так странно

У `<input type="file">` браузер рисует собственную кнопку «Выберите файл», которую **нельзя** привести к виду макета. Поэтому:

- настоящий file-инпут прячется визуально через `clip-path` — **не** `display: none` и не `visibility: hidden`, они выкинули бы его из порядка табуляции;
- видимую роль играет обёртка `<label>` с обычным `.input` внутри;
- фокус спрятанного инпута отражается на видимом поле правилом `.upl__input:focus-visible + .input` — иначе при табуляции подсветки не было бы вовсе.

Текстовое поле внутри — `readonly` и `tabindex="-1"`: оно только показывает, кликов и фокуса не принимает.

## Что компонент не рисует

| Часть | Откуда | Важное |
|---|---|---|
| Поле выбора | [awds-component-input](../awds-component-input/SKILL.md) | ступень задаёт мост `.upl--{N} .input` |
| Кнопка удаления | [awds-component-button](../awds-component-button/SKILL.md) | `btn-ghost btn--300` **+ обязательно `btn--icon-only`** |
| Индикатор загрузки | внешний компонент DS (M3 circular) | в arrow-components его нет — здесь только слот 20×20 |

**Про `btn--icon-only`**: без него кнопка выходит 48×36 вместо 36×36 и ломает строку. Я наступил на это при сборке — разметку вложенных компонентов надо брать из их скиллов, а не по памяти.

## Размеры

| Класс | Поле | Список | Высота с тремя файлами |
|---|---|---|---|
| `upl--300` | 36 | 120 | 164 |
| `upl--400` | 40 | 120 | 168 |
| `upl--500` | 48 | 120 | 176 |

**Размер меняет только поле.** Строка файла всегда 36px и набрана одинаково (имя 13/16, вес 12/16) — это видно прямо из ячеек макета: список везде ровно 120.

Зазоры: поле → список 8, между файлами 6, внутри строки 6. Все три не растут с размером.

## Геометрия строки

Превью, бокс иконки типа файла и кнопка удаления — три квадрата **36×36**, и все выражены одной формулой `rectangle-300: icon + 2 × padding`. Это не педантизм: кнопка — это `.btn--300`, собранная именно так, и превью обязано совпадать с ней по боксу, иначе строка перестанет быть ровной при изменении шкалы.

Длинное имя файла обрезается многоточием и не выталкивает кнопку за край — проверено на всех размерах.

## Ошибка по файлу

`.upl__file--error` красит **обе строки** — имя и вес — в `error-core`. Так в макете: цвет стоит на контейнере, а не на отдельной строке.

Модификатор вешается на конкретный `<li>`, а не на весь загрузчик: один файл может быть отклонён, остальные при этом нормальные. Вторая строка при ошибке — хорошее место для причины («12 Мб — больше допустимых 10») вместо веса.

## Доступность

- Список — настоящий `<ul>` с `<li>`: скринридер объявит, сколько файлов загружено.
- **Кнопка удаления должна называть файл**: `aria-label="Удалить wp.png"`, а не просто «Удалить». Иначе в списке из пяти файлов пять одинаковых кнопок.
- Индикатор загрузки — не только картинка: если процент важен, рядом нужен `aria-live` с текстом статуса.
- При ошибке цвет — не единственный сигнал: причина пишется текстом во второй строке.
- Инпут остаётся в потоке фокуса (см. выше) — загрузка доступна с клавиатуры.
