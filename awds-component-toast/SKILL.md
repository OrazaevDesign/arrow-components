# Toast (плашка-уведомление) ArrowDS

Короткое сообщение о том, что произошло: удалили товар, отправили форму, не прошла оплата. Слева иконка или кольцо обратного отсчёта, дальше текст, справа кнопка действия («Отменить») и крестик. Ничего не хардкодит: цвета — ячейки тона, размеры и тень — токены DS. См. скилл `arrow-design-system`.

Компонент **статичный** — это вид плашки. Показ, очередь, автоскрытие и отсчёт реализует потребитель.

## Когда что

| Нужно | Компонент |
|---|---|
| Сообщение о результате действия, поверх интерфейса, само уходит | **`awds-component-toast`** (этот) |
| Пояснение к элементу по наведению | `awds-component-tooltip` |
| Панель с хвостом под меню или календарь | `awds-component-popover` |
| Сообщение в потоке страницы, не поверх неё | `awds-component-notice` — счётчик на иконке; для полосы-объявления компонента пока нет |

## Тон и левый слот

Тон — **имя набора**, как у `button / primary` и `tooltip / default`: в Figma это два набора, `toast / normal` и `toast / alert`.

| Что | Класс | Значения |
|---|---|---|
| тон (имя набора) | `.toast-{тон}` | `normal` (тёмная плашка: островок темы) · `alert` (ошибка: `error-core`) |
| левый слот | класса нет | внутрь `.toast__icon` кладут либо иконку 20×20, либо `.toast__timer` |
| кнопка и крестик | класса нет | просто наличие узлов `.toast__action` и `.toast__close` |

В макете последние две строки — ось `lead=icon|timer` и булевы `show-action` / `show-close`. В коде классов под них нет: разница выражена тем, какие узлы лежат в разметке, а правый отступ контента подхватывает `:has()`. Такое расхождение осей макета и классов заложено и у `button` (ось `state` с шестым значением `loading`).

**До 21.09.2026** набор был один, с осями `variant=normal|alert` и `type=icon|control|timer`. Обе против канона `props.md`: слова-заглушки (правило 4), а `type` вдобавок кодировал две независимые вещи — что в левом слоте И есть ли контролы, хотя второе уже выражали булевы.

## Откуда берутся значения

| Что | Источник |
|---|---|
| Фон / текст (normal) | `--surface-bright-dark` / `--surface-on-highest-dark` — ячейки `toast/normal/*` в островке темы |
| Фон / текст (alert) | `rgb(var(--error-core))` / `rgb(var(--error-on))` — ячейки `toast/alert/*` |
| Тень | `var(--awds-shadow-elevation-3)` |
| Скругление | `var(--awds-rounded-border-radius-400)` (8) |
| Отступы | `--awds-space-2-5` (10) по краям, `--awds-space-1-5` (6) внутренними зазорами |
| Текст | шкала **control**: `--awds-control-font-size-400` (14/20); счётчик таймера `-200` (12/16) |
| Иконка и кольцо | `--awds-space-5` (20) |
| Подложка контрола при наведении | цвет контента под `--awds-opacity-20` |

**Тон normal — островок темы.** Ячейки ведут на роли по назначению (`surface/bright`, `surface/on-highest`), а тёмной плашку делает сам компонент, читая те же роли в dark-значении. Поэтому тост остаётся тёмным и в тёмной теме. Решение владельца 21.09.2026: «инверсия происходит на самом компоненте, а не в токенах».

Состояний у плашки нет; у контролов есть наведение. Маппинг зафиксирован в `component.meta.json` + `snapshot/figma.json`.

## Разметка

```html
<div class="toast toast-normal" role="status">
  <div class="toast__content">
    <span class="toast__icon">
      <svg viewBox="0 0 20 20" aria-hidden="true"><!-- иконка --></svg>
    </span>
    <span class="toast__text">Товар удалён</span>
  </div>
  <button class="toast__action" type="button">Отменить</button>
  <button class="toast__close" type="button" aria-label="Закрыть">
    <svg viewBox="0 0 20 20" aria-hidden="true"><!-- крестик --></svg>
  </button>
</div>
```

Кнопка и крестик необязательны: без них правый отступ контента возвращается сам.

**Таймер вместо иконки** — кольцо берётся у `awds-component-progress` (circular, determinate), у него размер и цвет вынесены ручками:

```html
<span class="toast__icon">
  <span class="toast__timer">
    <svg class="progress progress-circular" viewBox="0 0 48 48" style="--awds-progress-value: 80"
         role="progressbar" aria-valuenow="4" aria-valuemin="0" aria-valuemax="5"
         aria-label="Осталось секунд">
      <circle class="progress-circular__arc" cx="24" cy="24" r="23" pathLength="100"/>
    </svg>
    <span class="toast__timer-value">4</span>
  </span>
</span>
```

Своё кольцо в тосте не рисуется: это была бы вторая реализация той же вещи.

## Поведение: показ, очередь, отсчёт

Всё это — на стороне потребителя, компонент даёт только вид:

- **Появление** — по факту действия, не по загрузке страницы. Плашка не перекрывает элемент, которым пользователь только что воспользовался.
- **Автоскрытие** — по таймеру; обратный отсчёт показывается кольцом, если у сообщения есть отменяемое действие. Наведение курсора отсчёт останавливает, уход возобновляет.
- **Очередь** — одна плашка за раз; следующее сообщение ждёт, а не наслаивается.
- **Доступность:** контейнеру `role="status"` (вежливое объявление, не перебивает), у крестика — `aria-label`. Плашка с кнопкой действия не должна исчезать быстрее, чем её успевают прочитать: минимум 5 секунд или до наведения.

## CSS

Один файл — `references/toast.css` (база `.toast` + `.toast__content` / `__icon` / `__text` / `__timer` / `__action` / `__close` + тона `.toast-{normal,alert}`). Подключается один раз глобально.

Кольцо фокуса берёт цвет контента плашки: тост — тёмный островок, и общий `--awds-focus-color` (`surface-on-highest`) на нём не читался бы. Значение при этом не своё — это тот же цвет, что у текста.

Визуальный QA — `references/preview.html` (storybook): оба тона × иконка/таймер × с контролами и без, на светлой и тёмной теме.
