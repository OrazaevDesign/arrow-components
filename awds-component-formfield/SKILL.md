# Formfield ArrowDS

Поле формы целиком: подпись, контрол, пояснение, ошибка. Собственного оформления почти нет — компонент ставит четыре готовых куска в колонку с одним зазором и раздаёт им размерную ступень. Сам он рисует только пояснение и текст ошибки.

## Разметка

```html
<div class="fld fld--400">
  <label class="lbl" for="inn">
    <span class="lbl__body"><span class="lbl__text">ИНН</span></span>
  </label>

  <span class="input input-default">
    <input class="input__field" id="inn" aria-describedby="inn-desc">
  </span>

  <p class="fld__description" id="inn-desc">10 цифр для компании, 12 для ИП</p>
</div>
```

Ошибка — такой же абзац, только классом `fld__error`; показывать оба сразу можно, в макете они и стоят один под другим.

**Размерные классы вложенным ставить не нужно**: `.fld--400` сам раздаёт ступень подписи и контролу. Ставить `.lbl--400` и `.input--400` не требуется, а если поставить чужую ступень — мост всё равно победит (см. ниже).

## Что внутри

| Часть | Откуда | Класс |
|---|---|---|
| Подпись | [awds-component-label](../awds-component-label/SKILL.md) | `.lbl` |
| Контрол | [input](../awds-component-input/SKILL.md) · [select](../awds-component-select/SKILL.md) · [textarea](../awds-component-textarea/SKILL.md) | `.input` / `.select` / `.txa` |
| Пояснение | этот компонент | `.fld__description` |
| Ошибка | этот компонент | `.fld__error` |

Внутренности контролов и подписи копируются из их скиллов дословно — здесь они не переписываются.

## Размеры

| Класс | Подпись | Контрол | Пояснение | Высота поля |
|---|---|---|---|---|
| `fld--300` | 20 | 36 | 16 (12/16) | 100 |
| `fld--400` | 24 | 40 | 16 (13/16) | 108 |
| `fld--500` | 24 | 48 | 20 (14/20) | 124 |

Высота поля — при полном составе (подпись + контрол + пояснение + ошибка), как в ячейках макета. С `textarea` внутри она больше за счёт контрола: 140/148/164.

**Зазор между всеми четырьмя частями одинаковый — 4px, и он не растёт с размером.** Это проверяется сложением: 24+4+48+4+20+4+20 = 124.

## Ловушка: типографика пояснения

Напрашивается семантический `var(--awds-rectangle-{N}-description-*)` — он существует и на размерах 500 и 400 совпадает с макетом (14/20 и 13/16). **Но на 300 он даёт 13/16, а в макете там 12/16** — на ступень мельче. Поэтому маппинг сделан по значению: `control-400` / `control-300` / `control-200`.

Если `rectangle-300-description` однажды починят до 12/16, три строки в CSS можно будет свернуть обратно в семантику — но не раньше.

## Доступность

- **Пояснение связывается с контролом через `aria-describedby`** — иначе скринридер его не прочитает. Это не украшение: в пояснении обычно формат ввода, без него поле непонятно.
- **Текст ошибки — тоже `aria-describedby`**, плюс `aria-invalid="true"` на самом контроле. Если показаны и пояснение, и ошибка, в `aria-describedby` перечисляются оба id через пробел.
- Подпись связывается с контролом через `for` + `id` (или оборачиванием — см. скилл подписи).
- Цвет ошибки — единственный сигнал в макете, поэтому текст обязан объяснять, что не так и что делать. «Ошибка» в качестве текста ошибки не годится.
- У выключенного поля гаснет **только пояснение**: контрол и подпись гасятся своими правилами, а текст ошибки остаётся в полную силу — если поле недоступно и при этом ошибочно, эту ошибку тем более нужно видеть.

## Состояний у компонента нет

Оси State в макете нет: hover, focus, active и disabled принадлежат контролу. Единственное правило состояния здесь — приглушение пояснения у выключенного поля, **и оно выведено**, а не снято с ячейки.

## Refresh

```
обнови awds-component-formfield под Figma
```

ACB зайдёт в Figma по сохранённой ссылке (см. `component.meta.json`), вытащит актуальные variable_defs, сравнит со снапшотом, покажет diff и обновит CSS + preview. Документация (этот файл и `formfield-input.md`) — не трогается.

## Алгоритм использования

1. Возьми разметку из [references/formfield-input.md](references/formfield-input.md).
2. Подключи `formfield-input.css`, `label.css` и CSS нужного контрола.
3. Убедись, что на странице есть DS-токены и сайтовый `css-variables.css` с ролями под классом `.theme-default.theme-light` на `<html>`.
4. Поставь `.fld--{N}` (если не указан, действует 400) — подпись и контрол подхватят ступень сами.
5. Свяжи части: `for`/`id` у подписи, `aria-describedby` у пояснения и ошибки.

## Соседние компоненты

- **[awds-component-input](../awds-component-input/SKILL.md)**, **[awds-component-select](../awds-component-select/SKILL.md)**, **[awds-component-textarea](../awds-component-textarea/SKILL.md)** — контролы, которые встают в это поле. Все три сверены: состав и зазоры поля одинаковы, меняется только контрол.
- **[awds-component-input-combi](../awds-component-input-combi/SKILL.md)**, **[awds-component-select-combi](../awds-component-select-combi/SKILL.md)** — контролы с плавающей меткой. В макете для них есть отдельные `Formfiled Combi / *` (подписи снаружи там нет) — этот скилл их не покрывает.
- **Ещё не реализованы** из той же страницы макета: `Formfiled / FileUploader`, `Uploader`, `Formfiled / Square`, `Datepiker`, `DatepikerRange`.
