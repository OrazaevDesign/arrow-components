# Input Combi ArrowDS

Поле, у которого подпись живёт **внутри** контрола: пусто — стоит по центру и работает как placeholder, фокус или заполнено — уезжает наверх, уменьшается и освобождает строку значению. Размеры, цвета и типографика — из токенов DS, ничего не хардкодится. Общая картина токенов — `arrow-design-system`, регенерация этого скилла из Figma — `arrow-components-builder`.

## Разметка

```html
<span class="icombi icombi-default icombi--400">
  <span class="icombi__body">
    <input class="icombi__field" id="city" type="text" placeholder=" ">
    <label class="icombi__label" for="city">Город</label>
  </span>
</span>
```

Три вещи в этой разметке обязательны, и каждая ломает компонент, если её убрать:

- **`placeholder=" "`** (пробел) — на `:placeholder-shown` держится определение «поле пустое». Без атрибута метка навсегда останется наверху, поверх пустого поля. Сам placeholder невидим: его роль играет метка.
- **Порядок «поле, потом `<label>`»** — состояние «заполнено» ловится соседним комбинатором `+`, а он смотрит только вперёд.
- **Обёртка `__body`** — система координат для абсолютной метки. Без неё метка позиционируется от контейнера и уезжает под иконку `prefix`.

Варианты с иконками, кнопкой очистки и выключенным полем — в [references/input-combi-default.md](references/input-combi-default.md).

## Чем отличается от `awds-component-input`

Это **разные компоненты в Figma**, а не варианты одного, и разница не косметическая:

| | `input` | `input-combi` |
|---|---|---|
| Подпись | снаружи, `<label>` над полем | внутри рамки, уезжает наверх |
| Размеров | 7 (50…600) | **4** (300…600) |
| Разметка | поле + слоты | поле + метка внутри `__body` |
| Вертикаль поля | симметричная (`padding`) | асимметричная (`input-top` / `input-bottom`) |

Когда что: подпись снаружи **читается лучше** — она видна всегда и не конкурирует со значением. Combi берут, когда вертикали мало (плотная форма, модалка) или когда форма длинная и заполненные поля не должны терять названия. Форму мешать не стоит: либо все поля с плавающей меткой, либо все с внешней подписью.

## Откуда берутся значения

| Что | Источник | Где живёт |
|---|---|---|
| Цвета состояний (bg/chroma/border/текст/метка/иконка) | `rgb(var(--secondary-container-*))`, `rgb(var(--primary-container-*))`, `rgb(var(--surface-bright))` inline | `references/input-combi-default.css` |
| Кольцо фокуса | `var(--awds-focus-color-formcontrol)`, вариант Outside + Formcontrol | слой `awds-component-focus-selection` | Figma `focus-selection/outlineVariant` + `opacity/50` |
| Геометрия (padding/icon/rounded) | `var(--awds-rectangle-{N}-*)` | `component-token-map.json` → `map.size.rectangle` |
| Горизонтальный отступ текста и метки | `var(--awds-rectangle-{N}-text-gap)`, а со слотом — `padding` | Figma: проп `Padding Icon` у `Content Combi Input` |
| Вертикаль поля и метки | `var(--awds-rectangle-{N}-combi-{input-top , input-bottom , label-top})` | там же, ветка `combi` |
| Типографика значения | `var(--awds-rectangle-{N}-typography-*)` → `control-{M}` | там же |
| Типографика уехавшей метки | `var(--awds-control-200-*)` / `var(--awds-control-100-*)` | **маппинг ручной** — shape-токена нет |
| Opacity для disabled | `var(--awds-opacity-opacity-40)` | css-global (базовая шкала) |
| Базовая палитра | RGB-триплеты ролей `--{role}` | `css-variables.css` сайта |

**Базовый класс — `.icombi`, а не `.input-combi`.** Приватные аккумуляторы по контракту зовутся `--awds-{base_class}-*`; при `base_class = input-combi` они стали бы `--awds-input-combi-*`, что префиксом совпадает с чужим запрещённым `--awds-input-*` и ложно роняет sanity-check публикации. Тот же приём, что у `button-overhung` → `.obtn`.

## Размерные модификаторы

| Класс | Высота | Значение | Метка наверху | Когда |
|---|---|---|---|---|
| `icombi--300` | 36px | 14/20 | 11/16 | Плотные формы |
| `icombi--400` | 40px | 14/20 | 11/16 | **По умолчанию** — обычные формы |
| `icombi--500` | 48px | 16/20 | 12/16 | Ключевые поля |
| `icombi--600` | 52px | 16/20 | 12/16 | Тач-интерфейсы, крупные формы |

**Размеров четыре, а не семь.** У `50/100/200` combi-токены в css-global стоят в `space-0`: на высоте 32/24/20 px метке некуда уезжать. Нужно поле меньше 36px — бери `awds-component-input` с подписью снаружи, а не уменьшай combi.

Высота не задаётся явно и **совпадает с обычным полем того же размера**: строку значения сдвигают вниз на Δ и ровно на столько же поднимают низ. Ширина — `100%`; 320px в макете это ширина демо-фрейма.

## Пять вещей, которые легко сделать неправильно

1. **Забыть `placeholder=" "`.** Самая частая поломка: метка залипает наверху над пустым полем, и контрол выглядит вечно заполненным. Атрибут нужен именно пустой (пробел) — видимого placeholder в этом компоненте нет.
2. **Типографика метки — ручной маппинг, единственный в компоненте.** Для значения есть shape-токен, для уехавшей метки — нет. Взяты `control-200` (500/600) и `control-100` (300/400) по совпадению всех трёх свойств: font-size, line-height **и** letter-spacing. Не подменяй на `typography-*`: там на тех же номерах другой line-height.
3. **Уезд метки — не `transform: scale()`.** Соблазн дешевле анимировать масштабом, но у мелкой метки в макете своё letter-spacing (0.1–0.2%), а `scale` растянул бы межбуквенное вместе с кеглем. Анимируются `top` и свойства шрифта явным списком.
4. **Горизонтальный отступ — `text-gap`, если с этой стороны нет иконки**, и метка обязана ехать вместе с текстом. В макете горизонтали строк `label` и `input` всегда равны; если переключить только поле, метка при уезде прыгнет по горизонтали. Переключается по стороне: `:has(> .icombi__prefix)` двигает и `padding-left` поля, и `left` метки.
5. **Фокус гасит hover через `:not(:focus-within)`, а не порядком правил.** `:has()` в hover-селекторе даёт (0,5,0) против (0,2,0) у `:focus-within` — без `:not()` наведение на сфокусированное поле подменяло бы брендовую рамку серой.

## Доступность

- Поле остаётся нативным: клавиатура, автозаполнение, типы (`email`, `tel`, `search`), отправка формы работают сами.
- **Связь метки с полем — через `for` + `id`, и она обязательна.** `pointer-events: none` на метке гасит клики (чтобы попадали в поле), но не связь: скринридер читает метку как имя поля. Проверено по a11y-дереву — контрол объявляется как `textbox "Город"`.
- Метка **не исчезает при вводе** — в этом главное преимущество варианта перед полем с placeholder: заполненная форма не превращается в столбик значений без названий.
- Фокус виден при любом способе входа в поле (`:focus-within`); кольцо стоит **в 1px от рамки**, не вплотную.
- Длинная метка обрезается многоточием. Если подпись не помещается — это сигнал, что поле требует внешней подписи или подсказки под ним, а не более длинной метки.
- Декоративная иконка в слоте → `aria-hidden="true"`. Кликабельная (очистить, показать пароль) → внутри слота настоящий `<button type="button" aria-label="…">`.
- Disabled гасится `opacity: var(--awds-opacity-opacity-40)` на всей обёртке — макетное поведение, контраст в этом состоянии заведомо ниже AA. Рядом нужен текст-причина, а не только серость.

## Варианты

Семь — тот же набор, что у `awds-component-input`, и **палитра у них общая**: в Figma обе группы ячеек ссылаются на один `form-control/{вариант}/*`. Это не предположение по аналогии — хексы всех семи сверены со снапшотом обычного Input: 73 пары значений, 0 расхождений.

Выбор варианта — от **фона, на котором стоит поле**, а не от важности поля:

| Вариант | Класс | Фон в покое | Когда |
|---|---|---|---|
| **default** | `.icombi-default` | `secondary-container-core` — серый | Поле на белой странице |
| **light** | `.icombi-light` | `surface-bright` — белый | Поле на сером блоке: карточка, панель фильтров, модалка |
| **success** | `.icombi-success` | `success-container-core` — зелёный | Значение прошло валидацию |
| **error** | `.icombi-error` | `error-container-core` — красный | Значение не прошло валидацию |
| **autofill** | `.icombi-autofill` | `tertiary-container-core` — синий | Значение подставил браузер, а не пользователь |
| **ghost** | `.icombi-ghost` | прозрачный | Границу задаёт окружение: ячейка таблицы, инлайн-правка |
| **secondary** | `.icombi-secondary` | `secondary-core`, рамка в цвет фона | Второстепенное поле: фильтр, служебный ввод |

**success / error / autofill — это состояния значения**, а не виды контрола: класс вешается и снимается по ходу валидации. У `error` цвета мало — нужны `aria-invalid` и текст причины (см. [input-combi-error.md](references/input-combi-error.md)).

**Два варианта ведут себя не как все**, и это сверено по ячейкам макета:

- **ghost** — на hover и active **ничего не подсвечивается** (в макете все три ячейки прозрачны), поэтому правил в CSS нет намеренно. С плавающей меткой он опаснее, чем у обычного поля: в покое видна одна серая надпись без рамки и заливки, опознать контрол не по чему.
- **secondary** — hover меняет **фон**, а не рамку (рамка в цвет фона), кольцо фокуса **тёмное** `surface-on-highest` без альфы, а текст и метка при фокусе не перекрашиваются.

У остальных пяти вариантов при фокусе подсветка (зелёная / красная / синяя / серая) **полностью уступает брендовой** — фокус важнее статуса значения.

Цвета живут на классе варианта, база `.icombi` бесцветна (как `.btn` / `.btn-primary` у кнопки), поэтому класс варианта обязателен: `class="icombi icombi-default icombi--400"`.

| Вариант | Файл | Reference |
|---|---|---|
| default | `references/input-combi-default.css` | [input-combi-default.md](references/input-combi-default.md) |
| light | `references/input-combi-light.css` | [input-combi-light.md](references/input-combi-light.md) |
| success | `references/input-combi-success.css` | [input-combi-success.md](references/input-combi-success.md) |
| error | `references/input-combi-error.css` | [input-combi-error.md](references/input-combi-error.md) |

Каждый файл **самодостаточен**: содержит базу `.icombi` (побайтово одинаковую), четыре размера, свой блок варианта и reduced-motion. Подключается только нужный вариант; если нужны несколько — несколько файлов, дублирующаяся база безвредна.

## Refresh

При изменении токенов в Figma:

```
обнови awds-component-input-combi под Figma
```

ACB зайдёт в Figma по сохранённой ссылке (см. `component.meta.json`), вытащит актуальные variable_defs, сравнит со снапшотом, покажет diff и обновит CSS + preview. Документация (этот файл и `input-combi-default.md`) — не трогается.

## Алгоритм использования

1. Возьми разметку из [references/input-combi-default.md](references/input-combi-default.md) — с `placeholder=" "`, `id`/`for` и обёрткой `__body`.
2. Подключи CSS нужного варианта (`input-combi-{вариант}.css`) — один раз глобально.
3. Убедись, что на странице есть DS-токены (`--awds-rectangle-*`, `--awds-control-*`, `--awds-opacity-*`, `--awds-font-*`) и сайтовый `css-variables.css` с цветовыми ролями под классом `.theme-default.theme-light` на `<html>`.
4. Поставь класс варианта (`icombi-default`, `icombi-error`, …) — без него поле останется бесцветным, — размерный модификатор `.icombi--{N}` (если не указан, действует 400) и правильный `type`.
5. Ширину задай контейнеру-родителю: поле тянется на 100%.
