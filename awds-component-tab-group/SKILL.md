# Tab Group ArrowDS

Контейнер вкладок: держит ряд, раздаёт вложенным ступень, прокручивает ряд, когда
он не влезает, и несёт всю семантику вкладок, которую одна вкладка гарантировать
не может. Своих цветов и шрифтов у группы нет — их приносят вложенные компоненты.
Общая картина токенов — `arrow-design-system`, регенерация из Figma —
`arrow-components-builder`.

**Группа — не вкладка.** Одна вкладка с подчёркиванием — `awds-component-tab`;
плитка выбора вариации товара — `awds-component-tab-product`. Здесь контейнер, и
он состоит из инстансов чужих компонентов.

**Не путать с `button-group`.** Тот склеивает кнопки в один сегментированный
контрол встык и намеренно не знает ни ступени, ни ролей. Здесь — панель
навигации по разделам: есть ось `size`, есть мост ступени, есть `role="tablist"`
и клавиатура.

## Оси

| Ось | Значения | Как выражается |
| --- | --- | --- |
| вид | `boxed` · `separated` · `underline` | класс варианта `.tab-group-{вид}` |
| `size` | `400` · `300` | класс размера `.tab-group--{N}` |

Состояний у группы нет: `hover`, `focus`, `active`, `disabled` живут на вкладках.

**Один компонент, а не три.** У вариантов разный состав узлов (`boxed` и
`separated` собраны из `button`, `underline` — из `tab`; у `boxed` вдобавок
плашка), и по правилу 2 канона имён это ровно признак **варианта**: вариантом
становится то, что отвечает на вопрос «чем эта вещь является». Правило работает в
обе стороны — «две сущности с одинаковым составом узлов это один компонент с
осью», а разный состав узлов делает варианты, а не компоненты. Так же устроены
`price` (`sale` / `default` / `none`), `emblem` (`initials` / `img` /
`placeholder`) и `tab-product` (`text` / `img`). Роль у трёх наборов одна —
контейнер вкладок, ось одна, значения оси одинаковые: три компонента означали бы
три версии, три задачи и три места, где чинится одна и та же прокрутка.

## Разметка

Два элемента: корень и дорожка.

```html
<div class="tab-group tab-group-underline tab-group--400">
  <div class="tab-group__track scrollbar scrollbar-transparent"
       role="tablist" aria-label="Разделы товара">
    <button type="button" class="tab tab-selected" role="tab"
            id="tab-descr" aria-controls="panel-descr" aria-selected="true" tabindex="0">
      Описание
    </button>
    <button type="button" class="tab tab-unselected" role="tab"
            id="tab-specs" aria-controls="panel-specs" aria-selected="false" tabindex="-1">
      Характеристики
    </button>
  </div>
</div>

<div id="panel-descr" role="tabpanel" aria-labelledby="tab-descr" tabindex="0">…</div>
<div id="panel-specs" role="tabpanel" aria-labelledby="tab-specs" tabindex="0" hidden>…</div>
```

| Обязательно | Почему |
| --- | --- |
| `.tab-group` | корень: габарит, ограничение по ширине родителя, у `boxed` — плашка |
| `.tab-group-{вид}` | вид приносит зазор и оформление; без класса варианта группа безвидная |
| `.tab-group--{N}` | ступень раздаётся вложенным только отсюда |
| `.tab-group__track` | прокрутка и вылет под кольцо фокуса; без дорожки ряд обрежется по краю плашки, а кольцо — по краю дорожки |
| `role="tablist"` на **дорожке** | `tablist` обязан владеть элементами `role="tab"` напрямую; между корнем и вкладками стоит обёртка, поэтому роль не на корне |
| `aria-label` (или `aria-labelledby`) на дорожке | несколько панелей вкладок на странице иначе неразличимы на слух |
| `role="tab"` + `aria-selected` на каждой вкладке | выбранность выражена классом варианта, а класс — не семантика |
| `id` + `aria-controls` на вкладке, `role="tabpanel"` + `aria-labelledby` на панели | связь «вкладка ↔ панель» существует только в этой паре атрибутов |
| `tabindex="0"` у выбранной, `-1` у остальных | roving tabindex: из группы вкладок в порядке табуляции ровно одна остановка |

**Почему две обёртки, хотя в макете ячейка одна.** Каждой причины по отдельности
хватило бы:

1. **Прокрутка обрезает по padding-box.** Если прокручивается сама плашка
   `boxed`, её фон, радиус и обводка едут вместе с содержимым либо режут его по
   своему краю. Плашка обязана стоять, ехать обязан ряд.
2. **Кольцо фокуса в контейнер прокрутки не влезает.** `outline` рисуется за
   границей элемента и режется контейнером прокрутки. Дорожка получает вылет
   `calc(--awds-focus-width + --awds-focus-offset)` паддингом и тут же снимает
   его отрицательным полем: в раскладке высота не меняется, а кольцо целиком
   попадает в необрезаемую область. Замер: вылет 3 px, высота ряда те же 40 / 36.

**Ступень вложенным не пишется.** `.btn--400` и `.tab--400` в разметке отсутствуют
намеренно — см. «Мост ступени».

## Мост ступени

Ступень группы кормит size-аккумуляторы вложенного компонента:

| Вид | Мост | Что кормит |
| --- | --- | --- |
| `boxed`, `separated` | `.tab-group--{N} .btn` | `--awds-btn-padding`, `-gap`, `-rounded`, `-icon`, `-fs`, `-lh`, `-ls` |
| `underline` | `.tab-group--{N} .tab` | `--awds-tab-padding`, `-gap`, `-fs`, `-lh`, `-ls` |
| `underline`, счётчик | `.tab-group--{N} .tab .notice` | `--awds-notice-size`, `-pad-h`, `-pad-v`, `-fs`, `-lh`, `-ls` |

Мост весит `(0,2,0)` против `(0,1,0)` у size-класса вложенного, поэтому внутри
группы ступень **всегда диктует группа** — при любом порядке подключения файлов и
даже если потребитель напишет `.btn--300` руками. Тот же приём и то же следствие,
что у `formfield` с полем и у `tab` со счётчиком.

**Мост у `underline` двухзвенный.** Счётчик внутри вкладки не получает ступень от
собственного моста вкладки (`.tab--{N} .notice`), потому что класса `.tab--{N}` в
разметке нет — его как раз и заменил мост группы. Без второго звена счётчик на
ступени 300 остался бы четырёхсотым: у `.notice` дефолт базы 400. Дефект был бы
виден глазами, но молча.

**Отличие от `button-group`.** Тот моста не строит осознанно: у него нет оси
`size` вовсе, ступень пишется на каждой кнопке, и группа не хочет знать
`--awds-btn-rounded`. Здесь ось `size` у группы есть — две ступени в макете, — и
знание ступени приходит сверху; значит и раздавать её обязана группа.

## Переполнение

Решение Р7 от 01.09.2026: **горизонтальная прокрутка плюс покраска полосы
компонентом `scrollbar`.** Перенос на вторую строку отвергнут — он меняет высоту
контейнера и ломает шапку.

| Решение | Почему так |
| --- | --- |
| прокручивается **дорожка**, не корень | у `boxed` иначе поехала бы плашка; кольцо фокуса резалось бы по её краю |
| `.tab-group` = `inline-size: fit-content; max-inline-size: 100%` | хватает ряд, пока он влезает, и упирается в родителя, когда нет: контейнер прокрутки обязан быть уже своего содержимого |
| `.tab-group__track > * { flex: 0 0 auto }` | флекс-элемент по умолчанию отдаёт ширину раньше, чем появится прокрутка. Без правила вместо ряда со скроллом получился бы ряд сплющенных вкладок. У `.tab` такое правило своё есть, у `.btn` — нет |
| `overscroll-behavior-inline: contain` | домотанный до края ряд не пробивает прокрутку на страницу |
| `scroll-padding-inline` = зазор варианта | вкладка, на которую увели фокус стрелкой, не встаёт вплотную к обрезу и не читается как последняя |
| `scroll-behavior: smooth`, снятый под `prefers-reduced-motion` | гасим движение, не информацию |
| класс `scrollbar` ставит **потребитель** на дорожку | компонент полосы не задаёт `overflow` и размеры, а решение «где и насколько прокручивать» принадлежит группе; но CSS-файл полосы подключается отдельно, поэтому и класс пишется в разметке, а не навязывается селектором |

**Рекомендуется `scrollbar scrollbar-transparent`.** У `transparent` нет трека, и
полоса не рисует под вкладками серую линию, которой в макете нет; у `underline`
такая линия ещё и прочиталась бы разделителем.

**Цена, которую надо знать.** Классическая полоса прокрутки занимает 6 px и на
столько же поднимает высоту группы, **пока ряд переполнен**, — в браузерах, где
полосы не наложенные (Chrome и Firefox на Windows и Linux). На macOS, iOS и
Android полоса наложенная и места не занимает. Скачок на границе переполнения
снимается `scrollbar-gutter: stable` на дорожке, но компонент его не ставит:
резервирование места меняет раскладку и у группы, которая никогда не переполняется,
съело бы 6 px даром. Это решение блока.

**Чего в переполнении нет и почему:**

- **`scroll-snap`.** Полоса вкладок — не карусель: у вкладок разная ширина, «одна
  вкладка на экран» ритма нет, а прилипание спорило бы с `scrollIntoView`, которым
  клавиатурная навигация подводит вкладку под фокус. `mandatory` вообще запретил бы
  остановиться между вкладками.
- **Краевого затухания маской.** `mask-image` гасил бы вместе с содержимым и
  **кольцо фокуса** крайней вкладки, а включать затухание только на переполненной
  стороне можно лишь скролл-таймлайном (Chrome 115+). При этом аффорданс «есть ещё
  контент» уже даёт покрашенная полоса — ровно за этим её и выбрал Р7. Второй
  аффорданс ценой видимости фокуса не покупается.
- **Кнопок-стрелок по краям.** Их нет в макете, и они требуют своей разметки и
  своего JS.

## Доступность — контракт этого компонента

`tab` намеренно не берёт на себя ничего, что требует существования панели. Всё
это — здесь.

**Разметка** (обязательна, таблица выше): `role="tablist"` на дорожке с
`aria-label`; `role="tab"` + `aria-selected` + `id` + `aria-controls` на каждой
вкладке; `role="tabpanel"` + `aria-labelledby` + `tabindex="0"` на каждой панели;
roving `tabindex` (`0` у выбранной, `-1` у остальных).

**Клавиатура** — поведение, которое обязан реализовать потребитель. Компоненты
ArrowDS своего JS не возят, но контракт поведения описывают:

| Клавиша | Что делает |
| --- | --- |
| `Tab` | входит в группу на выбранную вкладку и уходит из группы целиком — внутри одна остановка, а не пять |
| `→` / `←` | переносит фокус на следующую / предыдущую вкладку, с заворотом по кругу; `tabindex` переставляется на неё |
| `Home` / `End` | первая / последняя вкладка |
| `Enter` / `Space` | активирует вкладку при **ручной** активации |
| `Tab` из вкладки | уводит фокус в открытую панель, а не на следующую вкладку |

**Автоматическая или ручная активация.** Автоматическая (панель меняется вместе с
фокусом) — когда содержимое панели уже на странице и переключение бесплатно.
Ручная (`Enter` / `Space`) — когда панель грузится запросом: иначе перебор
стрелками выстреливает столько запросов, сколько вкладок в ряду.

**Выключенные вкладки фокус не получают** и пропускаются стрелками. Выключенная
вкладка обязана нести нативный `disabled`: `pointer-events: none` гасит мышь, но
не клавиатуру.

**Вкладку, на которую увели фокус, надо подвести в видимую область** —
`el.scrollIntoView({ block: 'nearest', inline: 'nearest' })`. Отступ у обреза
компонент уже отвёл (`scroll-padding-inline`).

**Если переключение секций — это навигация** (адрес меняется, страница
перезагружается), то это не вкладки: `role="tablist"` обещает панели на той же
странице. Тогда ряд ссылок в `<nav>`, `button-area` или `list-item`.

## Что берётся из темы

| Что | Источник |
| --- | --- |
| зазор панели (`underline`) | `--awds-size-tabs-{400\|300}-gap-panel` |
| зазор между кнопками (`separated`) | `--awds-size-tabs-{400\|300}-gap-button` |
| внутренний отступ плашки (`boxed`) | `--awds-space-0-5` |
| радиус плашки (`boxed`) | `--awds-rounded-border-radius-600` / `-400` |
| фон плашки (`boxed`) | роли `--surface-dim` → `--surface-surface`, вертикальный градиент |
| обводка плашки (`boxed`) | роль `--surface-dim`, толщина — `own_values` |
| приподнятость выбранной кнопки (`boxed`) | `--awds-shadow-elevation-1` из слоя производных |
| геометрия кнопок | `--awds-size-rectangle-{400\|300}-*` через мост |
| геометрия вкладок | `--awds-size-rectangle-{400\|300}-*` через мост |
| геометрия счётчика | `--awds-size-notice-{400\|300}-*` через мост |
| вылет под кольцо фокуса | `--awds-focus-width` + `--awds-focus-offset` из `awds-component-focus-selection` |

**Гашения у группы нет.** Выключенной бывает вкладка, а не панель вкладок;
`state/opacity/control-disabled` применяет `tab` и `button` у себя. Если панель
целиком неактивна, это `disabled` на каждой вкладке, а не полупрозрачный
контейнер: контейнер, погашенный целиком, гасит и подписи, которые обязаны
остаться читаемыми.

**Своё значение одно** — толщина обводки плашки `1px`: ячейки толщины линии в теме
нет (`Space/px` — шкала отступов, не толщин). Заявлено в `own_values`.

## CSS-файлы

Три файла, по одному на вариант, **каждый самодостаточный**: база, ступени,
вариант, мост. Тот же приём, что у `button` с его восемью файлами, и обратный
приёму `tab` с одним файлом на два варианта. Разница по существу: у вкладки
выбранная и невыбранная живут в одном ряду одновременно, поэтому им нужен один
файл; вид группы потребитель выбирает один раз, и подключать два файла ради
одного вида не за что.

Из этого следует, где что объявлено: плашка `boxed` и зазоры вариантов стоят на
классе **варианта**, а не в базе. Иначе потребитель, подключивший рядом
`tab-group-boxed.css` и `tab-group-underline.css`, получил бы фон плашки и на
панели с подчёркиванием.
