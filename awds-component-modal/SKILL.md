# Modal (окно поверх страницы) ArrowDS

Окно, которое перекрывает страницу и требует решения: подтверждение, форма, фильтры, длинный текст. Шапка с заголовком, прокручиваемое содержимое, подвал с кнопками. Два вида — **диалог** по центру и **панель** у края экрана. Ничего не хардкодит: цвета — ячейки, размеры и тень — токены DS. См. скилл `arrow-design-system`.

Компонент строится на нативном `<dialog>`: ловушку фокуса, Esc и инертность страницы даёт платформа, а не скрипт потребителя.

## Когда что

| Нужно | Компонент |
|---|---|
| Окно с решением поверх страницы: подтвердить, заполнить, выбрать | **`awds-component-modal`** (этот) |
| Панель у края экрана: фильтры, корзина, детали | тот же компонент, вид `.mdl-sidepage` |
| Сообщение о результате, само уходит | `awds-component-toast` |
| Панель с хвостом у якоря: меню, календарь | `awds-component-popover` |

## Вид и брейкпоинт

Вид — **имя набора**, как у `progress / linear` и `progress / circular`: в Figma это два набора, `modal / dialog` и `modal / sidepage`.

| Что | Класс | Значения |
|---|---|---|
| вид (имя набора) | `.mdl-{вид}` | `dialog` (по центру, скруглён) · `sidepage` (панель у края, без скругления) |
| брейкпоинт | класса нет | адаптив даёт медиазапрос: ниже 1068px оба вида становятся шторкой снизу |

Разница видов — **только геометрия**: диалог скруглён со всех сторон и стоит по центру, панель прижата к краю во всю высоту и скруглений не имеет — у края экрана их нечем показать. На мобильном оба превращаются в шторку снизу со скруглёнными верхними углами; так нарисованы обе ячейки `view=mobile`.

**Ось `view=desktop|tablet|mobile` в макете — это брейкпоинт, а не вариант** (правило 10 канона `props.md`). Классa под неё нет: размеры и отступы приходят из темы, которая сама переключает их по ширине. Решение владельца 22.09.2026: ось в макете оставлена как наглядное сравнение трёх раскладок.

## Части

Три части в макете — `. / header`, `. / content`, `. / footer`. После прохода 22.09.2026 у них нет осей-заглушек: состав задают булевы.

| Часть | Что внутри | Чем управляется |
|---|---|---|
| шапка | кнопка «назад», заголовок, крестик | `show-back`, `show-title`, `show-close`, текст `title` |
| содержимое | слот, текстовый блок, поле формы, полоса прокрутки | `show-swap`, `show-text`, `show-field`, `scrollbar`, слоты `swap` и `field`, ось `padding=on|off` |
| подвал | слот, две кнопки | `show-swap`, `show-start`, `show-end`, слоты `start` и `end`, ось `reverse=on|off` |

До 22.09.2026 части держали 23 ячейки с комбинациями в именах (`title+back`, `text+input`), опечаткой `pozitive`, состоянием `delete-hover` и булевой осью `alter-align=false|true`. Стало 5 ячеек.

## Откуда берутся значения

| Что | Источник |
|---|---|
| Фон окна | `rgb(var(--surface-bright))` — ячейка `modal/bg` |
| Подложка | `rgb(var(--surface-on-highest) / var(--awds-opacity-50))` — ячейка `modal/backdrop`, альфа задаётся компонентом |
| Тень | `var(--awds-shadow-elevation-4)` — у окна четвёртая ступень, не третья |
| Скругление | `var(--awds-rounded-border-radius-600)` (10) |
| Боковые отступы | `var(--awds-layout-section-gutter)` — 24 на десктопе, 16 ниже, адаптив внутри темы |
| Шапка | сверху `--awds-space-8` (32), снизу `--awds-space-2` (8) |
| Подвал | сверху `--awds-space-2` (8), снизу `--awds-space-6` (24) |
| Заголовок | `--awds-typography-font-size-800` + `--awds-typography-line-height-compact-800` (18/22) |
| Текст | `--awds-control-font-size-400` (14/20) |

**Заголовок раньше стоял на роли старой библиотеки** `title/t5` — 18/22 на десктопе и 17/20 ниже. В новой теме эти ступени не адаптивны; решением владельца 22.09.2026 взято десктопное значение фиксом, разница в 1px на мобильном снята.

## Разметка

```html
<dialog class="mdl mdl-dialog" aria-labelledby="mdl-title">
  <header class="mdl__header">
    <h2 class="mdl__title" id="mdl-title">Удалить адрес?</h2>
    <button class="btn btn-ghost btn--200 mdl__close" type="button" aria-label="Закрыть">
      <svg viewBox="0 0 20 20" aria-hidden="true"><!-- крестик --></svg>
    </button>
  </header>

  <div class="mdl__content">
    <p class="mdl__text">Адрес пропадёт из списка доставки. Это нельзя отменить.</p>
  </div>

  <footer class="mdl__footer">
    <button class="btn btn-secondary btn--300" type="button">Отмена</button>
    <button class="btn btn-primary btn--300" type="button">Удалить</button>
  </footer>
</dialog>
```

Открывается `dialog.showModal()`, закрывается `dialog.close()`. Имя окну даёт заголовок: `<h2 class="mdl__title">` несёт `id`, а `<dialog>` — `aria-labelledby` на него; без этой пары скринридер объявит окно безымянным. Кнопка «назад» — `.mdl__back` первой в шапке, кнопки подвала — обычные `awds-component-button`.

Содержимое во всю ширину (таблица, список, карта) — `.mdl__content--flush`: боковые отступы приносит само содержимое. Порядок кнопок подвала меняет `.mdl__footer--reverse`.

## Поведение

- **Ловушка фокуса, Esc и инертность страницы** приходят от `showModal()`. Своего JS для этого писать не нужно.
- **Прокручивается только содержимое**, шапка и подвал остаются на месте; `overscroll-behavior: contain` не даёт прокрутке уехать на страницу под окном.
- **Появление** — переход по `@starting-style` (Baseline 2024). Не поддержано — окно появится без анимации, функция не страдает.
- **Движение уважает `prefers-reduced-motion`**: переходов нет вовсе.
- A11y: заголовку — `<h2>` внутри `.mdl__header`, окну — `aria-labelledby` на него; крестику — `aria-label`.

## CSS

Один файл — `references/modal.css` (база `.mdl` + `.mdl__header` / `__title` / `__content` / `__text` / `__footer` + виды `.mdl-{dialog,sidepage}` + модификаторы `--flush` и `--reverse`). Подключается один раз глобально.

Базовый класс **`.mdl`, а не `.modal`**: `.modal` — имя компонента в Bootstrap, почти наверняка занятое у потребителя, а приватные аккумуляторы по контракту зовутся `--awds-{base_class}-*`. Тот же приём, что у `label` → `.lbl`, `datepicker` → `.dpick`.

Визуальный QA — `references/preview.html` (storybook): оба вида, три состава шапки, содержимое с отступами и без, подвал в обе стороны.
