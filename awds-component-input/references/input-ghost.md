## Когда

Границу поля задаёт окружение: строка таблицы, инлайн-правка, ячейка.

Фон, chroma и рамка **прозрачны во всех состояниях покоя**. Поле опознаётся только по тексту и по кольцу при фокусе.

**Не используй ghost как единственное поле формы.** Пользователь не увидит, куда писать: нет ни рамки, ни заливки, а на hover ничего не подсвечивается. Ghost работает там, где поле уже обрамлено чем-то другим — ячейкой таблицы, строкой списка, панелью.

## Чем отличается

**Hover не объявлен вовсе — и это не упущение.** В макете ячейки Rest, Hover и Active дают `#ffffff00` во всех трёх свойствах: наведение здесь ничего не подсвечивает. Пустое правило в CSS было бы враньём, поэтому его нет.

При фокусе фон и рамка остаются прозрачными — меняются только цвет текста и кольцо.

Всё остальное — структура, слоты, семь размеров, геометрия, типографика, доступность, нативный крестик у `type="search"`, кнопка в слоте — совпадает с Default до значения и описано в [input-default.md](input-default.md).

## HTML

```html
<span class="input input-ghost input--400">
  <input class="input__field" type="text" placeholder="Значение">
</span>
```

Меняется только класс варианта.

## Состояния

| Состояние | Селектор |
|---|---|
| Rest | `.input-ghost` |
| Focus | `.input-ghost:focus-within` |
| Disabled | `.input:has(> .input__field:disabled)` — на базе, общее для вариантов |

Про `:not(:focus-within)` в hover / active — см. [input-default.md → Состояния](input-default.md#состояния): порядок правил там не работает, потому что `:has()` поднимает специфичность выше фокуса.

## CSS

`input-ghost.css` — файл **самодостаточный**: та же база `.input`, что и у остальных вариантов (побайтово), плюс блок `.input-ghost`. Подключается только нужный вариант.
