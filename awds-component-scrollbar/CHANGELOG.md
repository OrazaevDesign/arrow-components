# Changelog — awds-component-scrollbar

Формат: версия · дата · уровень. Уровень описывает работу потребителя: MAJOR — править
разметку, MINOR — ничего, PATCH — пересобрать копию CSS. Флаг `visual_change` отдельно
отмечает, изменился ли вид.

## 2.0.6 — 2026-09-15 — PATCH · visual
Якоря #cell обёрнуты в комментарий /* */. Голый якорь, введённый 15.09.2026, комментарием не является: парсер CSS считает его битым объявлением и отбрасывает вместе со всем до следующей точки с запятой, то есть съедает следующую строку. Восстановлены цвета ползунка (--awds-scrollbar-thumb и -hover). Снимок стилей показал ноль изменений, потому что полоса живёт на псевдоэлементах ::-webkit-scrollbar*, которые он не обходит.
Потребителю: Пересобрать копию CSS: блокам уедет исправленная секция.

Потребителю: Ничего делать не нужно: вид тот же.

## 2.0.4 — 2026-09-15 — PATCH

Потребителю: Ничего делать не нужно: изменились только комментарии в CSS.

## 2.0.0 — 2026-08-29 — MAJOR
Вариант clear переименован в transparent. Имя теперь называет то, что меняется: трек берёт роль role/surface/transparent — именно её биндит ячейка макета. Прежнее clear было единственным в системе словом на эту идею, второе — transparent у list-item; два слова на один смысл схлопнуты в одно. Вариант light, стоявший в макете до этого, не подошёл: light у нас не прилагательное, а ТОН со своей группой ячеек (state/form-control/light/* у семи компонентов, state/range/light/* у range), а у полосы группы State нет вовсе — роли инлайнятся.
Потребителю: В разметке: .scrollbar-clear → .scrollbar-transparent. Вид не меняется, значения те же. Потребителей в блоках нет, но компонент опубликован — пересобрать dist и storybook.

## 1.0.0 — 2026-08-28 — INIT
Компонент собран из макета (node 2093:4230, 8 ячеек: Type × Style × State). Класс красит
нативную полосу прокрутки: толщина 6px, ползунок 4px за счёт прозрачной рамки, стили
Default (трек surface/dim) и Clear (трек прозрачный), наведение 40% → 70%. Своей
разметки и JS нет. Стандартные свойства для Firefox разведены с webkit-псевдоэлементами
через @supports — иначе Chrome 121+ игнорирует точную геометрию.
Потребителю: новый компонент, у потребителей его пока нет.
